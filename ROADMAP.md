# AiGhost — Evidence-Led Roadmap

This roadmap separates software evidence from future physical research. Dates and completion estimates are intentionally omitted until owners, resources, and acceptance criteria are agreed.

## Stage 1 — Evidence and release hygiene

- Repeat focused and wider regression tests on a recorded commit.
- Resolve the currently blocked Vercel account statuses or document the alternative verified build path.
- Establish a clean, reproducible build and a dated live-route check.
- Complete an IP/contributor and third-party licence review.
- Finalise the public scope, privacy documentation, support process, and security review plan.

**Exit evidence:** tagged source revision, archived test logs, repeatable build evidence, verified deployment record where applicable, and completed ownership/licence review.

## Stage 2 — Home Node pilot hardening

- Deliver a signed, maintainable node client and installer for supported desktop platforms.
- Make owner consent, node revocation, token lifecycle, and user-visible resource limits clear.
- Add measurable operational telemetry without collecting unnecessary personal content.
- Test sleep/offline recovery, queue expiry, revocation, and failure handling on real devices.
- Obtain an independent review of the node threat model and update policy.

**Exit evidence:** documented device matrix, repeatable pilot, independent security findings, and complete user-facing terms.

## Stage 3 — Neuroplasma laboratory validation

- Identify compatible optical hardware and a qualified laboratory partner.
- Build an isolated physical loopback before attempting integration with live AiGhost services.
- Measure wavelength, optical power, loss, delay, error rate, switching behaviour, and repeatability.
- Evaluate persistent memory materials separately from fibre transport and delay lines.
- Compare measured results with the existing software model and publish deviations.

**Exit evidence:** instrumented lab report, reproducible measurements, identified hardware bill of materials, and independent technical review.

## Stage 4 — Commercial collaboration

Potential collaboration areas include product pilots, local-first software integrations, supported node clients, optical research partnerships, and negotiated software licensing or strategic technology discussions.

Any financial instrument, share issuance, token arrangement, public fundraising, or paid offer must be separately structured and reviewed by qualified legal and financial professionals before it is communicated as an offer.
